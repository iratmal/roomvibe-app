U Edit Artwork nestanu “Artwork 2/3/4” (i/ili se slike gube nakon refresh/edit)

Problem: Uploada se više slika (npr. 4 različite), ali:

nakon refresh ili ponovnog ulaska u edit, dio slika nestane

u Edit Artwork UI ostane samo Cover (ili npr. 1–2 slike)

u konzoli/network se ranije vidjelo “Image failed to load: /api/artwork-image/:id” i “File not found”

Root cause (vjerojatno):

backend ne vraća stabilan set image referencea (ili se overwrite-a array)

mapping “slot index → image id/key” nije stabilan

kod edit save/update briše postojeće slike ako nisu ponovno poslane

file key path mismatch (obj store), pa endpoint vraća “File not found”

Expected:

Artwork mora trajno čuvati sve uploadane slike u istim slotovima (1..N).

Refresh stranice / edit / save ne smije obrisati postojeće slike.

Ako korisnik ne dira Artwork 2/3/4/5 — one moraju ostati.

Implementation requirements:

U bazi držati slike kao ordered list sa stabilnim “position/index” (1..max).

Update endpoint ne smije “replace” cijeli array osim ako je to namjera; treba patch logika:

dodaj novu sliku u točan slot

delete radi samo kad user klikne X

/api/artwork-image/:id mora pouzdano pronaći file u object storageu (provjeriti key naming i direktorije).

Acceptance criteria:

Uploadaj 4 različite slike → refresh → i dalje su 4 prisutne u Edit formi.

Klik Edit → i dalje su sve prisutne.

Nema “File not found” za postojeće slike.
