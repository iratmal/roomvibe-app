Task — Fix Password Sync Bug (Login vs Change Password)
Goal

Fix the authentication bug where the password used for login is different from the password stored and updated in Settings → Change Password.

Currently:

The user can log in with one password

But the Settings password change system does not recognize the same password

After changing password, the user sometimes cannot log in anymore

This means the login authentication and password update logic are not using the same password source or hashing method.

Required Fix

Ensure that:

Login

Password change in Settings

Password validation

ALL use the same password field and hashing logic.

The system must behave like this:

Password used during login = password stored in database

Password change updates that same password

After password change → login must work immediately with the new password

Old password must stop working

Technical Checks

Please verify:

1️⃣ Password Storage

Check the users table.

There must be only one password field, e.g.:

password_hash

Login and password update must both read/write this field.

2️⃣ Hashing Consistency

Ensure the same hashing library is used everywhere.

Example:

bcrypt.compare()
bcrypt.hash()

Login must compare the password with the same hashing algorithm used when updating the password.

3️⃣ Fix Change Password Logic

Current issue suggests that:

current password check is incorrect

OR password hash comparison is wrong

Fix so that:

compare(currentPassword, user.password_hash)

works correctly.

4️⃣ Ensure Login Uses Updated Password

After password change:

login endpoint must read the updated hash

session must work normally

Test Case (Required)

Use this exact test account:

Email:

user@test.app

Password must be set to:

usertest

Then verify:

Login works with usertest

Change password in Settings

Logout

Login again with the new password

Old password must fail

Stop Condition

The task is complete only when:

Login password = Settings password

Password change works correctly

No desynchronization exists

User can log in immediately after password change
