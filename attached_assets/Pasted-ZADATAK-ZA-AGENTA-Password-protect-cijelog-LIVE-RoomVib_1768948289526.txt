ZADATAK ZA AGENTA: Password protect cijelog LIVE RoomVibe sajta (bez diranja koda)

Cilj:
Privremeno zaključati cijeli LIVE RoomVibe site tako da se pri otvaranju bilo koje stranice (uključujući home) traži jedan password (jedan user/pass ili samo password), i da nitko tko nema taj password ne može vidjeti ništa.
Rješenje mora biti izvan aplikacijskog koda (bez promjena u repo kodu), i mora se moći ugasiti jednim klikom (npr. toggle / disable pravilo) bez deploya.

Prioritet

LIVE domena (glavna domena) – staging nije bitan.

Zahtjevi (obavezno)

Ne diraj kod u repozitoriju (nema middleware-a, nema izmjena ruta, nema refactora).

Implementirati zaštitu na razini hostinga / edge-a (npr. Cloudflare Access / Vercel password protection / reverse-proxy basic auth / neki “site lock” mehanizam ovisno gdje je hostano).

Mora pokriti sve rute: /, sve dashboarde, sve public stranice, sve assete.

Mora biti reverzibilno jednim klikom: disable pravilo / disable policy / disable protection (bez promjena koda, bez deploya).

Ne smije “razbiti” live — nakon unosa passworda sve radi normalno kao i do sada.

Implementacijska pravila (kako)
Preferirano rješenje (najbolje)

Cloudflare Access / Cloudflare Zero Trust ispred domene:

Napraviti policy “Require authentication” ili “Require password / one-time access” (najjednostavnije).

Alternativno: Basic auth na edge-u ako postoji opcija.

Postaviti tako da je default: deny, a allow samo uz lozinku.

Ako Cloudflare nije opcija

Iskoristiti hosting-level password protection koji nudi platforma gdje je LIVE hostan (npr. zaštita deploymenta ili site-wide auth na reverse proxyu).

Bitno: i dalje bez promjena koda.

Tajne / sigurnost

Password (ili user/pass) postaviti preko platform settings / secrets (ne hardkodirati nigdje).

Agent neka mi kaže gdje je točno postavio (u kojem dashboardu/sekciji), da ja kasnije mogu ugasiti.

Deliverables (što mi trebaš poslati kad završiš)

Kratko: gdje si točno uključio zaštitu (npr. Cloudflare Zero Trust → Access → Applications → [ime] → Policies).

Koji je mehanizam: “Cloudflare Access” / “Basic Auth na proxy” / “Platform password protect”.

Točan “on/off” korak: kako ja ugasim zaštitu jednim klikom (npr. Disable policy toggle).

Potvrda testiranja:

Otvori site u incognito → traži password → bez passworda se ne vidi ništa

Nakon passworda → sve radi normalno

Acceptance criteria (test)

 Otvaranje LIVE domene u incognito traži password odmah (na home).

 Bez passworda ne vidi se ništa (ni dashboard ni javne stranice).

 S passwordom sve radi kao prije.

 Zaštita se može ugasiti jednim klikom u postavkama (bez deploya i bez promjena koda).

Napomena

Ovo je privremeni “private mode” dok ne implementiramo pravu registraciju i sigurniji auth flow unutar appa.
